# Qwen3.6-27B SFT Guide

This document describes how to perform SFT (supervised fine-tuning) on Qwen3.6-27B with MindSpeed-MM.
For training results and the training process report, see the [practice report](../../../docs/llm_sft/qwen36_ascendc/qwen36_ascendc_sft_report.md).

Example environment and version information:

- CANN: 9.0.0
- Hardware: Atlas A3 NPU, 16 dies

## Obtaining the Code

Run the following commands in your working directory to obtain the specified MindSpeed-MM revision and apply the patch provided by this project:

```bash
git clone https://gitcode.com/Ascend/MindSpeed-MM.git
cd MindSpeed-MM
git checkout aaed711fd4750857f104e8d832766ed915ff9ef0

git apply --check ../mindspeed-mm.patch
git apply ../mindspeed-mm.patch
```

Run all subsequent commands from the `MindSpeed-MM` root directory. If the patch file is not in the parent directory, replace `../mindspeed-mm.patch` with its actual path.

## Environment Setup

### 1. Set Up the CANN Environment

First, set up the driver, firmware, and CANN Toolkit according to the Ascend software installation guide. This example uses **CANN 9.0.0**.

Make sure the CANN environment variables are active. For example, run the following command for the actual installation path:

```bash
source /usr/local/Ascend/cann/set_env.sh
```

### 2. Set Up the Python Environment

Conda is recommended for Python package management:

```bash
conda create -n qw36-sft python=3.11 -y
conda activate qw36-sft

bash scripts/install.sh --msid eb10b92
pip install transformers==5.2.0 accelerate==1.2.0
pip install triton-ascend==3.2.1 \
  --extra-index-url https://mirrors.huaweicloud.com/ascend/repos/pypi

# If ModuleNotFoundError: No module named 'pkg_resources' occurs, use an older setuptools version
pip install setuptools==81.0.0
```

## Downloading and Converting the Base Model

### 1. Download the Model

Model download links:

ModelScope: https://www.modelscope.cn/models/Qwen/Qwen3.6-27B

Hugging Face: https://huggingface.co/Qwen/Qwen3.6-27B

Place the Qwen3.6-27B weights in Hugging Face format in the following directory. The directory name must match the configuration files:

```text
MindSpeed-MM/ckpt/hf_path/Qwen3.6-27B/
```

The directory should contain the model weights, configuration files, and tokenizer files, such as `config.json`, `*.safetensors`, and `tokenizer.json`.

### 2. Convert to DCP Format

The example configurations enable `init_model_with_meta_device`, so convert the Hugging Face weights to DCP before training:

```bash
bash cvt_ckpt_hf2dcp.sh
```

The script uses fixed input and output paths. Modify the script if you need different paths:

```text
Input:  ckpt/hf_path/Qwen3.6-27B
Output: ckpt/dcp_path/Qwen3.6-27B
```

After conversion, the output directory should contain `release/` and `latest_checkpointed_iteration.txt`. The `training.load` setting in the configuration must point to `ckpt/dcp_path/Qwen3.6-27B`, not directly to the `release/` subdirectory.

## Preparing and Converting the Data

### 1. Download the Data

Dataset download link: https://gitcode.com/cann/cann-recipes-train/discussions/2

### 2. Generate the Dataset

Use the `data_generator` provided in this repository to generate the dataset. During generation, it calls the `prompt_generator` provided in this repository to create prompts:

```bash
python path-to-data_generator/generate_data.py \
  --source-root path-to-data \
  --output-dir path-to-generated-data \
  --filter-ops exp foreach_addcdiv_scalar foreach_norm gelu masked_scale mish sigmoid swi_glu \
               apply_adam_w apply_rotary_pos_emb arg_max cross_entropy_loss cummin dynamic_quant gather gcd \
               grid_sampler_3d group_norm maximum resize_bilinear rms_norm scatter softmax unsorted_segment_sum \
  --clean
```

The data processing scripts in this project accept JSONL files. Each line must be a JSON object in one of the following formats:

```json
{"instruction": "Task description", "input": "Task content", "output": "Answer"}
```

or:

```json
{"prompt": "Task content", "response": "Answer"}
```

The `instruction`/`input`/`output` format requires the `input` and `output` fields. When `instruction` is non-empty, it is concatenated with `input` using a newline. The `prompt`/`response` format requires both fields.

The dataset generated by the `data_generator` provided in this repository uses the first format above.

### 3. Place the JSONL Files

Create the data directories in the MindSpeed-MM root directory and place the training data there:

```bash
mkdir -p data/jsonl data/json
```

The default example expects the following two files:

```text
data/jsonl/ops-data.jsonl
data/jsonl/sampled-data.jsonl
```

You can change the file names, but update `data.dataset_param.basic_parameters.dataset` in the YAML configuration accordingly.

### 4. Convert to Training JSON

Run the batch conversion:

```bash
bash cvt_data_format_jsonl2json.sh \
  'data/jsonl/*.jsonl' \
  'data/json/*.json'
```

The converted files are written to `data/json/` and are automatically loaded by the example configuration through `./data/json/*.json`. The script validates the JSON syntax, object type, and required fields on every line. It exits with an error if the input is invalid; fix the input and run it again.

## Launching Training

Place the configuration files provided by this project in `MindSpeed-MM/examples/qwen3_6`. The example configurations are:

```text
Packing full-parameter SFT
examples/qwen3_6/qwen3_6_27B_config_packing64k_gbs2.yaml

Unpacking full-parameter SFT
examples/qwen3_6/qwen3_6_27B_config_gbs16.yaml

Unpacking LoRA SFT
examples/qwen3_6/qwen3_6_27B_config_LoRA_gbs8.yaml
```

Before training, verify that the following paths in the configuration match your local directories:

- `data.dataset_param.preprocess_parameters.model_name_or_path`: Original Hugging Face model directory
- `data.dataset_param.basic_parameters.dataset`: Converted JSON data
- `model.model_name_or_path`: Original Hugging Face model directory
- `training.load`: Converted DCP directory
- `training.save`: Training output directory

### 1. Launch Full-Parameter SFT

Start training in the background (16 NPUs are used by default):

```bash
# Use the packing configuration
bash run_train_nohup.sh \
  examples/qwen3_6/qwen3_6_27B_config_packing64k_gbs2.yaml

# Use the unpacking configuration
bash run_train_nohup.sh \
  examples/qwen3_6/qwen3_6_27B_config_gbs16.yaml
```

The script starts training when the NPUs are idle and writes the PID file and workflow logs under `logs/`. After successful training, it automatically runs checkpoint format conversion post-processing. Post-processing is not run if training fails.

### 2. Launch LoRA SFT

Start training in the background (16 NPUs are used by default):

```bash
bash run_train_nohup.sh \
  examples/qwen3_6/qwen3_6_27B_config_LoRA_gbs8.yaml
```

The script starts training when the NPUs are idle and writes the PID file and workflow logs under `logs/`. After successful training, it automatically runs checkpoint merge post-processing. Post-processing is not run if training fails.

## Checkpoint Post-Processing

Using the packing full-parameter SFT configuration as an example, training outputs are written to `./outputs/packing64k-gbs2` by default. When the training workflow completes normally, checkpoint format conversion is performed automatically. To manually convert the DCP checkpoints for all iterations to Hugging Face format, run:

```bash
bash cvt_ckpt_dcp2hf_batch.sh \
  ./outputs/packing64k-gbs2 \
  ./outputs/packing64k-gbs2-hf \
  examples/qwen3_6/qwen3_6_27B_config_packing64k_gbs2.yaml
```

The script iterates over the `iter_*` directories under the input directory and writes each result to an output directory with the corresponding iteration suffix. By default, the original Hugging Face model directory is `ckpt/hf_path/Qwen3.6-27B`, from which tokenizer and other files are read.

To convert only one DCP checkpoint:

```bash
bash cvt_ckpt_dcp2hf.sh \
  ./outputs/packing64k-gbs2-iter_000010 \
  ./outputs/packing64k-gbs2/iter_000010
```

To preview the checkpoints that the batch script would process without performing the conversion, set:

```bash
CHECKPOINT_POSTPROCESS_DRY_RUN=1 bash cvt_ckpt_dcp2hf_batch.sh \
  ./outputs/packing64k-gbs2 \
  ./outputs/packing64k-gbs2-hf \
  examples/qwen3_6/qwen3_6_27B_config_packing64k_gbs2.yaml
```
